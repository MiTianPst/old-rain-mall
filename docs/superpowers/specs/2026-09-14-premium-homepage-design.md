# 旧雨电商暖白轻奢首页设计

## 目标

将当前只有搜索、分类和商品网格的首页升级为以商品成交为核心的综合商城首页。页面采用暖白轻奢科技风格，保持亲切、可信和现代感，并确保首页出现的商品、库存、销量、会员折扣和购物车操作都来自真实业务数据。

## 技术约束

- Next.js 16.3.5，遵循仓库内 `node_modules/next/dist/docs/` 的当前版本文档。
- React 19.2.8、TypeScript 5.9.3 严格模式。
- Tailwind CSS 4.3.3，不新增独立业务 CSS 文件。
- MySQL 8.4 与 Drizzle ORM 0.45.2。
- 数据获取默认使用 Server Component；只有快速加购等交互使用 Client Component。
- 面向用户的 UI 文案与必要代码注释使用中文。
- 不引入新的 UI 或图标依赖，图标使用内联 SVG 或文本表达。

## 视觉方向

- 主色为暖白、象牙白和燕麦色，正文使用深灰，强调色使用克制的琥珀色或焦糖色。
- 首屏使用明亮的科技产品大图、柔和日光、轻微磨砂玻璃与低强度阴影。
- 商品卡片保持清晰的信息密度，不使用黑金奢侈品风格、霓虹赛博风或拥挤的平台促销风。
- 桌面端突出横向运营内容；移动端使用单列或双列重排，不直接压缩桌面布局。

## 页面结构

1. 顶部服务公告：全场包邮、两小时订单保留、会员折扣和售后提示。
2. 主导航：品牌、商品分类入口、购物车、地址、订单、登录或会员信息。
3. 首屏：品牌主张、搜索框、“立即选购”和“查看新品”按钮、主推商品视觉。
4. 分类快捷入口：展示分类名称、商品数量和对应的科技品类视觉。
5. 运营入口：限时优惠、新品首发和热销排行。
6. 心悦会员：展示三级门槛与折扣；登录用户额外显示当前等级和升级进度。
7. 商品总览：保留真实搜索、分类筛选、结果数量、商品网格与分页。
8. 服务保障：全场包邮、模拟支付、售后保障和订单可追踪。
9. 完整页脚：购物指南、服务支持、关于旧雨和版权信息。

## 商品运营模型

在 `products` 增加以下字段：

- `compareAtPriceCents: number | null`：可选划线原价，必须大于当前展示价格才显示。
- `isFeatured: boolean`：是否进入首页推荐池。
- `featuredSort: number`：推荐商品升序排序，数值越小越靠前。
- `promotionLabel: string | null`：最长 30 个字符的运营标签，例如“新品首发”或“限时优惠”。

现有 `createdAt` 作为上新时间。热销数量不保存为可编辑字段，而是聚合已成功支付且未退款订单的 `order_items.quantity`。退款订单不计入热销榜。

后台商品新增和编辑表单需要支持上述字段。原价为空表示无划线价；推荐顺序必须为非负整数；促销标签为空表示不显示。

## 首页数据契约

首页服务返回 `HomepageData`：

- `featuredProducts`：最多 6 个在售、分类可见、存在有效 SKU 的推荐商品。
- `newProducts`：最多 6 个符合公开条件的商品，按 `createdAt`、`id` 倒序。
- `bestSellingProducts`：最多 6 个符合公开条件的商品，按有效销量倒序；销量相同按创建时间倒序。
- `categories`：公开分类及每个分类下符合公开条件的商品数量。

所有首页商品卡片均包含默认 SKU、实时库存、划线价、促销标签和真实销量。运营区没有数据时允许隐藏；商品总览仍须正常展示。

## 价格与会员规则

- 商品卡片主价格使用默认在售 SKU 价格。
- `compareAtPriceCents` 只有在大于主价格时才显示，禁止制造负优惠或零优惠。
- 已登录用户根据当前 `membershipLevel` 计算会员参考价：普通会员无折扣，心悦 1 级 9.8 折、心悦 2 级 9.5 折、心悦 3 级 9 折。
- 首页会员价只作当前会话下的实时预览，最终订单价格仍由现有结算服务重新计算并保存快照。
- 促销价与会员折扣按现有结算口径执行：商品当前 SKU 价格是会员折扣的基础金额。

## 交互规则

- 首屏搜索提交到 `/#catalog`，并保留 `search`；分类筛选、排序和分页继续使用 URL 参数。
- 分类卡片跳转到 `/?category=<slug>#catalog`。
- 单一有效 SKU 的商品支持快速加入购物车；多 SKU 商品显示“选择规格”并进入详情页。
- 未登录用户点击快速加购后跳转登录页，并将当前首页 URL 作为安全回跳地址。
- 加购成功后显示中文状态反馈，并重新验证购物车和首页头部数据。
- “立即选购”滚动到商品总览；“查看新品”滚动到新品区域。

## 组件边界

- `src/app/page.tsx`：解析查询参数，并行获取首页、分类、商品列表和会话数据。
- `src/features/home/*`：首屏、分类入口、运营专区、会员区、服务保障和页脚内容。
- `src/features/catalog/product-card.tsx`：通用商品卡片展示价格、标签、销量和库存。
- `src/features/catalog/quick-purchase.tsx`：唯一需要客户端状态的首页快速购买入口。
- `src/server/services/homepage-service.ts`：组合首页 DTO、会员展示价和运营区降级规则。
- `src/server/repositories/homepage-repository.ts`：推荐、新品和热销查询。

## 性能与错误处理

- 首页独立查询并行执行，避免串行等待。
- 首屏图片设置高加载优先级，其他商品图片保持懒加载。
- 数据库异常由页面错误边界显示中文错误信息；单个空运营区不视为错误。
- 查询必须限制返回数量；不把全部商品或订单加载到内存后排序。
- 首页的真实销量聚合仅处理有效订单状态，并依赖订单和订单项现有索引；如查询计划显示需要，再追加 `order_items.product_id` 索引。

## 无障碍与响应式

- 搜索框、导航和商品区具有明确标签及标题层级。
- 焦点状态可见，颜色不能作为库存或操作状态的唯一提示。
- 交互按钮最小触控高度 44px。
- 桌面端商品总览最多四列，平板两列，窄屏单列；运营卡片在窄屏纵向排列。

## 验收标准

- 首页视觉与已确认的暖白轻奢科技方向一致。
- 推荐、新品、热销、分类数量、库存、价格和会员价均来自数据库或既有会员规则。
- 搜索、分类、分页、商品详情与安全回跳保持可用。
- 单 SKU 可直接加购，多 SKU 必须选择规格，库存不足不能加购。
- 后台可以配置推荐、推荐顺序、划线原价和促销标签。
- 无运营数据时商品总览仍可用。
- 桌面端和手机端均没有横向溢出，关键中文文案完整可读。
- 通过相关单元测试、`npm.cmd run typecheck`、`npm.cmd run lint` 和 `npm.cmd run build`。

## 本阶段不包含

- 收藏、浏览历史、猜你喜欢、优惠券、秒杀库存和个性化推荐。
- 真实第三方支付、真实物流接口或新的售后规则。
- 额外 UI 组件库、图标库或分析埋点平台。
