# 旧雨电商后台管理设计

## 目标与范围

为旧雨电商增加仅管理员可访问的后台管理子系统，覆盖后台概览、商品管理、分类管理和订单管理。后台沿用现有 Next.js App Router、Server Component、Server Action、Drizzle ORM 与 MySQL 分层，不新增独立管理服务。

本阶段不包含用户管理、退款、物流接口、批量导入、图片上传和数据报表。自动化测试、集成测试和代码审查按当前开发安排，在全部项目功能完成后统一处理。

## 权限边界

- `/admin/**` 页面和所有后台 Server Action 都必须重新读取数据库 Session，并在服务端确认 `users.role === "ADMIN"`。
- 隐藏导航或按钮不构成权限控制；普通用户和匿名用户不得读取后台数据或执行写操作。
- 匿名访问后台跳转登录页；已登录普通用户展示无权限页面或返回 404，不泄露后台数据。
- Action 只接收操作所需的白名单字段，不接受角色、订单金额、支付状态、会员等级或累计实付金额。

## 分层结构

- `src/features/admin/**`：Zod 输入 Schema、表单和交互组件。
- `src/server/services/admin-*.ts`：管理员鉴权后的业务命令、状态限制和稳定中文错误。
- `src/server/repositories/admin-*.ts`：Drizzle 查询、唯一冲突映射、乐观锁更新和订单状态事务。
- `src/app/admin/**`：Server Component 页面读取与组装。
- `src/app/actions/admin-*.ts`：Session 鉴权、FormData 解析、服务调用和路径刷新。

## 商品管理

后台提供商品列表、搜索、状态筛选、新增和编辑。可写字段严格对应现有 Schema：分类、名称、slug、摘要、描述、整数分价格、库存、状态和封面地址。

- `slug` 依赖数据库唯一索引；重复时返回稳定的中文冲突错误。
- 价格在界面输入人民币元，边界层严格转换为整数分后再进入服务层，不使用浮点元保存。
- 编辑提交携带 `version`，更新使用 `id + version` 条件并递增版本，冲突时提示刷新页面后重试。
- 商品不提供硬删除。删除语义统一为 `ARCHIVED`，确保历史订单的商品外键和快照长期可读。
- `DRAFT`、`ACTIVE`、`ARCHIVED` 使用数据库现有枚举，不新增状态。

## 分类管理

后台提供分类列表、新增、编辑、排序和 `ACTIVE/HIDDEN` 状态切换。

- 可写字段为名称、slug、描述、排序值和状态。
- `slug` 依赖数据库唯一索引，重复时返回中文冲突错误。
- 分类不执行硬删除；停用统一设置为 `HIDDEN`。
- 隐藏分类后，其商品即使是 `ACTIVE` 也不再出现在公开商城或允许结算，但历史订单保持可读。

## 订单管理

后台提供订单号搜索、状态筛选、分页列表和订单详情。详情展示订单状态、支付状态、用户标识、地址快照、商品快照、金额明细和关键时间。

后台只开放两个显式命令：

```text
PAID -> SHIPPED -> COMPLETED
```

- `markShipped` 只允许已支付订单变为已发货，并写入 `shippedAt`。
- `markCompleted` 只允许已发货订单变为已完成，并写入 `completedAt`。
- 不提供任意状态下拉修改，不允许修改订单金额、支付状态、库存、地址快照或会员快照。
- 待支付订单的取消、超时关闭和库存恢复继续使用现有用户订单服务，不在后台重复实现。

## 页面与交互

- `/admin`：商品、分类、订单数量及待处理订单入口。
- `/admin/products`、`/admin/products/new`、`/admin/products/[id]/edit`。
- `/admin/categories`，使用同页新增和编辑表单。
- `/admin/orders`、`/admin/orders/[orderNo]`。
- 后台布局提供独立中文导航和返回商城入口；所有表单有 pending、字段错误、业务错误、空状态和危险操作确认。
- 页面默认使用 Server Component 获取数据，仅表单状态、确认对话框和提交按钮使用 Client Component。

## 数据一致性与错误处理

- 商品与分类唯一冲突由数据库唯一索引兜底，并映射为稳定业务错误。
- 商品编辑使用 `version` 乐观锁避免后台多人覆盖更新。
- 订单状态转换使用条件更新或事务锁，保证只有合法前置状态能成功转换。
- 数据库异常只记录到服务端，不把 SQL、连接信息、Session 或用户隐私返回浏览器。
- 成功写入后使用 `revalidatePath` 刷新后台页面和受影响的公开商城页面。

## 验收标准

- 匿名用户和普通用户无法读取或操作后台。
- 管理员可以新增、编辑、上下架和归档商品，公开商城及时反映状态。
- 管理员可以新增、编辑、排序和隐藏分类，隐藏分类不再公开展示。
- 管理员可以搜索和筛选订单，并按合法顺序发货、完成订单。
- 后台不能修改订单金额、支付状态、会员等级或累计实付金额。
- 所有金额仍为整数分，所有用户可见文案为中文。
