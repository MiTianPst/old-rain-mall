# 购物车完善设计

## 目标

在现有登录用户购物车基础上补齐数量修改、删除、实时库存校验、可结算合计和操作反馈，并完成公开商品模块审查发现的安全加固。

## 行为

- 数量修改为精确覆盖，范围为 1–99，且不能超过商品实时库存。
- 更新和删除均从数据库 Session 派生用户 ID，查询条件同时包含 cartItemId 与 userId。
- ACTIVE 商品只有在所属分类也为 ACTIVE 时才可加入或更新。
- 已下架、隐藏分类或库存不足的已有购物车项显示“不可结算”，但仍允许删除。
- 商品合计与总件数只统计可结算项。
- 修改和删除使用 Server Action，成功后刷新 /cart；每行显示独立的中文 pending、成功或失败状态。
- “去结算”链接指向下一阶段 /checkout；没有可结算商品时禁用。

## 公开模块加固

- 三个公开 API 对未知服务异常统一返回 500：error code 为 INTERNAL_ERROR，中文提示为“服务暂时不可用，请稍后重试”。
- 服务器只记录错误类型和安全上下文，不把数据库连接串、Cookie、Token 或异常原文返回客户端。
- 商品图片仅接受单斜杠开头的站内绝对路径，拒绝双斜杠、反斜杠和控制字符。

## 验证

- 单元测试覆盖更新、删除、所有权、不合法数量、库存不足和可结算合计。
- MySQL 集成测试覆盖隐藏分类商品拒绝加入、跨用户更新/删除失败和重复累加。
- 完成后运行 test、lint、typecheck、build，并用登录用户在页面验证数量修改和删除。
